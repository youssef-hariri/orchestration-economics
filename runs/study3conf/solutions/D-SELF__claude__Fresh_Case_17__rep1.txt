## PART 3: SHARED TECHNOLOGY CORE (INVARIANT ACROSS ALL MARKETS)

### 3.1 Adaptive Algorithm Architecture

#### Core Components (Identical Across Countries)

**1. Bayesian Knowledge Tracing (BKT)**

The platform estimates student mastery probability using Bayes' theorem:

```
P(Learned | Performance History) = 
  Probability student has learned skill, given observed responses
  
Updated after each attempt via:
  - Item difficulty (calibrated via IRT)
  - Learning rate (how quickly students learn)
  - Slip rate (probability of knowing skill but answering incorrectly)
  - Guess rate (probability of unknown skill but guessing correctly)
  
Mastery threshold: P(L) ≥ 0.80 on ≥3 independent items
```

**2. Item Response Theory (IRT) Calibration**

Each assessment item calibrated with three parameters:
- **Difficulty (b)**: How hard is the item for average student
- **Discrimination (a)**: How well does item distinguish high/low performers
- **Guessing (c)**: Probability of correct answer by guessing alone

These parameters are **calibrated per country** via field testing (100–200 students per item), but the **model is identical** across Vietnam, Saudi Arabia, France, Kenya.

**3. Reinforcement Learning (RL) for Adaptive Sequencing**

RL algorithm optimizes:
```
Maximize: Learning Gain per Unit Time
Subject to: Curriculum Constraints (no cross-grade, respect sequence, prerequisites)

Action space: Select next item from {eligible_items}
Eligible items = {items where prerequisites mastered} ∩ {items in current grade}
Not eligible = {items outside grade} ∪ {items with unmet prerequisites}
```

**Curriculum Constraint Integration** (Critical for Vietnam/France):

```json
{
  "algorithm_config": {
    "curriculum_framework": "MOET_2018",  // OR MOE_2030, MEN_SOCLES, CBC_2017
    "grade_level": 4,
    "adaptive_constraints": {
      "allow_cross_grade_acceleration": false,     // BLOCKED in Vietnam/France
      "allow_prerequisite_skipping": false,        // BLOCKED all countries
      "allow_topic_reordering": false,             // BLOCKED all countries
      "allow_within_grade_depth_variation": true   // ALLOWED (only flexibility)
    }
  }
}
```

**Within-Grade Adaptation** (How Platform Adapts in Rigid Curricula):

For advanced students who master content quickly:
- Don't accelerate to next grade (blocked by constraint)
- Instead: **deepen cognitive understanding within same topics**
  - Procedural fluency → Conceptual understanding → Transfer/application
  - Same topics; increased cognitive demand
  - Maintains grade-level cohort (addresses Vietnamese classroom structure concern)

**Example** (Grade 4 Multiplication, Vietnam):
```
Typical Student Path:
  Week 1–2: Multiplication procedural fluency (2-digit × 1-digit)
  → Mastery achieved → Move to next topic

Advanced Student Path:
  Week 1: Multiplication procedural fluency
  Week 2: Conceptual deepening (why is multiplication commutative? area model)
  → Mastery achieved → Move to next topic
  → Same grade, same topic sequence, increased depth
```

### 3.3 Offline-First Architecture (Critical for Rural Adoption)

#### What Works Offline

✓ Read problem / view content
✓ Attempt response / receive immediate feedback
✓ Request hint (pre-cached)
✓ Store responses locally (synced later)

#### What Requires Network

✗ AI adaptive recommendation (requires server-side BKT computation)
✗ Teacher dashboard updates (batched at sync time)
✗ New content download (incremental sync)

#### Sync Behavior

**Trigger**: Network available (WiFi or mobile data)
**Actions**:
1. Upload offline responses (correctness re-validated server-side)
2. Download new content (if curriculum updated)
3. Calculate AI recommendations server-side
4. Notify student: "Synced 24 items; 3 new recommendations available"

**Conflict Resolution**:
- Server is source-of-truth
- If data conflicts: student warned, server version wins
- No data loss (offline attempts stored; just marked "superseded")

**Storage Requirements**:
- Full curriculum cache: 150–200 MB (optional; user controlled)
- Minimal cache (current unit): 50–75 MB (standard)
- Battery impact: ~5% per nightly sync (acceptable)

## PART 4: COUNTRY-SPECIFIC CURRICULUM ADAPTATION LAYER

### 4.1 Vietnam: Curriculum Localization Strategy

#### 4.1.1 Curriculum Alignment Framework

**Vietnamese Education System**:
- **Grades 1–5**: Primary (foundational literacy + numeracy)
- **Grades 6–9**: Lower secondary (subject specialization)
- **Grades 10–12**: Upper secondary (tracks: science/humanities/technical)
- **Mandatory Curriculum**: MOET 2018 revision; no substitution permitted
- **Language**: Vietnamese K–12; English (grades 3+) supplementary
- **Exam Structure**: 
  - KCPE equivalent: Not formal; but monthly/quarterly assessments by schools
  - High School Exam (THPT): Gate to university entry (high-stakes)

**Platform Adaptation**:
- Respect grade-level grouping: No cross-grade acceleration
- Respect mandatory sequences: Cannot skip topics
- Support depth variation: Advanced students deepen understanding within grade level
- Exam-aligned: Items calibrated to match THPT exam format/difficulty

#### 4.1.2 Content Localization: Language & Cultural Adaptation

**Localization Process** (Timeline: Months 1–6):

| Phase | Duration | Deliverable | Owner |
|-------|----------|-------------|-------|
| **Month 1–2** | Hire curriculum team (1 director + 2 specialists) + translate 50 core items | Baseline translation quality established | Vietnam Curriculum Director |
| **Month 2–4** | Translate 500 core items (math grades 3–6) | 500 items translated + culturally adapted | Content Specialists |
| **Month 4–5** | Teacher review panel (10–15 Vietnamese teachers) reviews 20% sample | Feedback on language clarity, cultural appropriateness | Curriculum Director + Teachers |
| **Month 5–6** | Field testing in 5 tutoring centers (100+ students) | Item difficulty calibrated; IRT parameters estimated | Data Analyst + Teachers |

**Language Standards**:
- **Primary language**: Vietnamese (modern standard, grade-appropriate)
- **Readability**: Avoid Sino-Vietnamese terms where possible; use colloquial Vietnamese
- **Text direction**: LTR (Vietnamese uses Latin script; no RTL needed)
- **Diacritical marks**: Full support for Vietnamese diacritics (ă, ê, ô, đ, etc.)

**Cultural Localization Checklist**:

| Element | Standard | Example ✓ | Example ✗ |
|---------|----------|-----------|-----------|
| **Problem Context** | Use Vietnamese cultural references; avoid foreign unless unavoidable | "Anh Minh mua 3 quyển sách ở Hà Nội" (Minh buys books in Hanoi) | "John buys books at the store" |
| **Units/Measurements** | Metric system (Vietnamese standard) | 5 mét, 250 grams | 16 feet, 8 ounces |
| **Currency** | Vietnamese Dong (VND) | "Một quyển vở có giá 5000 đồng" | References to USD |
| **Dates/Calendar** | Gregorian calendar; Vietnamese holidays noted | Tet Lunar New Year reference | Western-only holidays |
| **Religious Content** | Secular; no religious references (but socialism-aligned acceptable) | Neutral math problems | References to Buddhism/Catholicism or anti-government rhetoric |

### 4.3 France: Privacy-First & Teacher Autonomy Positioning

#### 4.3.1 Laïcité & Pedagogical Philosophy Alignment

**Laïcité** (French Secularism):
- Not just "no religious content" (that's US secular)
- Means: **Separation of religion AND ideology from public education**
- Implies: Platform cannot impose individualistic "personalized learning" as neoliberal worldview
- Requires: Ideological neutrality; emphasis on collective values

**Platform Positioning for France**:

| Positioning Dimension | Recommended | Avoid |
|----------------------|------------|-------|
| **Learning Philosophy** | "Supports teacher's pedagogical judgment; complements human instruction" | "Personalized learning paths"; "engagement optimization" (sounds neoliberal) |
| **Student Agency** | "Supports students in achieving national competency standards" | "Student-driven learning"; "self-paced pathways" (sounds individualistic) |
| **Data Philosophy** | "Privacy-first; student data stays with school; no corporate analytics" | "Learning analytics"; "engagement metrics"; "personalization based on behavior" |
| **Teacher Role** | "Amplifies teacher expertise; reduces grading burden; frees time for deeper pedagogy" | "Personalizes instruction algorithmically"; "AI supplements teacher judgment" |
| **Assessment** | "Supports formative assessment aligned with national standards" | "Adaptive testing"; "continuous assessment tracking"; "predictive analytics" |

**Republican Values Integration**:
- Platform emphasizes **collective learning** (class-wide dashboards) alongside individual progress
- No social comparison/leaderboards (violates Republican equality principle)
- No student data visible to peers (protects dignity)
- Content must be values-neutral (no ideological messaging)

#### 4.3.2 Teacher Union Negotiation (Pre-Requisite for Pilot)

**Union Negotiation Process** (Months 1–3, before any pilot):

**Step 1: Stakeholder Mapping**
- Identify major unions: SNES (largest), FO, CGT, UNSA
- Contact: Union representatives for education/technology committees
- Agenda: Present platform, discuss concerns, negotiate agreement

**Step 2: Key Union Concerns & Responses**

| Union Concern | Platform Response | Contractual Commitment |
|--------------|------------------|----------------------|
| "Will platform be used to evaluate teacher performance?" | "No. Platform collects student learning data only. Teacher data explicitly excluded." | Written guarantee: "Platform data never used for teacher evaluation." |
| "Will algorithm replace teacher?" | "No. Algorithm handles practice/drill. Teacher handles conceptual instruction, values education, classroom culture." | Written guarantee: "Technology is supplement, never replacement." |
| "Will teachers be required to use platform?" | "Teachers decide adoption; school head cannot mandate. Voluntary participation." | Written guarantee: "Teacher opt-in; can withdraw consent anytime." |
| "Who pays for training?" | "Training is paid work time (union standard)." | Contract: "Professional development compensation per union rates." |
| "Will teacher data be shared with ministry?" | "No. Only student learning data, if school consents." | Written guarantee: "Teacher data access restricted to school only." |

**Step 3: Formal Agreement (MOU)**

Draft memorandum of understanding (MOU) specifying:
1. Platform cannot collect/report teacher performance metrics
2. Teacher data access restricted to teacher + school head
3. Training time is paid; compensation per union standard
4. Teachers opt-in to pilot (voluntary)
5. Data sharing with MOE requires school consent + teacher notification
6. Pilot evaluation criteria (how success is measured; union input on design)

**Step 4: Pilot Design Co-Design**

Union representative participates in:
- Pilot school selection
- Success metrics definition
- Training curriculum design
- Feedback collection mechanisms

**Timeline**: Months 1–3 negotiation + MOU signing; Month 4 pilot launch (if agreement reached).

**Risk Mitigation**: If union refuses negotiation, abandon government/school procurement; focus on B2C + private schools instead.

#### 4.3.3 GDPR Compliance & Privacy Differentiation

**GDPR Full Compliance** (Strict):
- Data processing agreement (DPA) with school + MOE
- Data Protection Impact Assessment (DPIA)
- Biennial audits by independent auditor
- Right to erasure: student data deleted upon request within 30 days
- Transparency: parents can request all data collected on child

**Competitive Differentiation**:
- Most US EdTech platforms are US-headquartered; GDPR compliance expensive/difficult
- Position as "European-designed, GDPR-native" ← competitive advantage vs. US platforms
- Emphasize: "Your student data stays in Europe, never transferred to US"

**Marketing Message**:
> "Unlike US EdTech platforms, we are GDPR-native. Student data is encrypted, stays in EU, and is never shared with US companies or advertisers. Teachers control what data is collected. This is learning technology designed for European values."
