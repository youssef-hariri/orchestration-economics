## EXECUTIVE SUMMARY

This framework provides **actionable, quantified guidance** for building culturally inclusive and accessible global products. It addresses language localization, design considerations, accessibility compliance, payment and legal requirements, governance structures, and pre-launch verification—all with concrete implementation details, real-world examples, and measurable success criteria.

**Key Features:**
- Tier-based language strategy (Tier 1 professional translation, Tier 2 machine translation + review, Tier 3 automated)
- Orthogonal preference system (language independent from region, currency, timezone)
- WCAG 2.2 AA compliance with intersectional accessibility scenarios
- Regional legal compliance (GDPR, CCPA, PDPA, India DPA 2023)
- Payment localization by region (tax, compliance, payment methods)
- High-context vs. low-context communication guidance
- Governance framework with escalation paths and accountability
- Quantified metrics for imagery, accessibility, localization quality
- Pre-launch checklist with binary pass/fail criteria

**Suitable for:** E-commerce, fintech, SaaS, social platforms, educational products, government/civic tools, healthcare products, and any global digital product serving diverse user populations.

## 1.1 Language and Locale Management

### 1.1.1 Orthogonal Preference Architecture

**Problem:** Systems conflating language with locale exclude bilingual users, expats, and diaspora communities. A Portuguese speaker in the USA cannot select Portuguese language + USD currency + US holidays + US phone format.

**Solution:** Decouple all user preferences into independent selections.

#### Database Schema

```javascript
{
  user_id: "user_12345",
  preferences: {
    // Language: Content and UI (independent)
    language: "pt",
    language_secondary: "en",
    
    // Region: Formatting, holidays, standards (independent)
    region: "us",
    
    // Currency: Display and transactions (independent)
    currency_primary: "usd",
    currency_secondary: "brl",
    
    // Timezone: Scheduling, notifications (independent)
    timezone: "America/New_York",
    
    // Formatting: Date, time, numbers
    date_format: "mm/dd/yyyy",
    time_format: "12h",
    
    // Accessibility
    text_size: "100%",
    dyslexia_font: false,
    high_contrast: false,
  }
}
```

document.getElementById('locale-preferences').addEventListener('submit', async (e) => {
  e.preventDefault();
  const formData = new FormData(e.target);
  const prefs = Object.fromEntries(formData);
  
  // Save to localStorage (offline access)
  localStorage.setItem('user-preferences', JSON.stringify(prefs));
  
  // Save to server (if signed in)
  if (window.isSignedIn) {
    await fetch('/api/user/preferences', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(prefs)
    });
  }
  
  // Apply preferences
  applyPreferences(prefs);
});

function applyPreferences(prefs) {
  // Set language and direction
  document.documentElement.lang = prefs.language;
  const rtlLanguages = ['ar', 'he', 'ur', 'fa'];
  if (rtlLanguages.includes(prefs.language.split('-')[0])) {
    document.documentElement.dir = 'rtl';
    document.body.classList.add('rtl');
  } else {
    document.documentElement.dir = 'ltr';
    document.body.classList.remove('rtl');
  }
  
  // Store for app-wide use
  window.userPreferences = prefs;
  
  // Reload content in new language
  reloadContent(prefs.language);
}
</script>

### 1.1.2 Language Support Strategy: Tier-Based Model

**Principle:** Equal investment across all languages is unsustainable. Tier-based approach balances inclusivity with resources.

#### Tier 1: Full Professional Localization

**Investment:** 100% | **Timeline:** 3–4 months | **Maintenance:** Per release

**Quality Standard:** Professional translators, native speaker review (2+), QA testing, terminology consistency, no machine translation.

**Tier 1 Languages:**

| Language | Code | Speakers | Markets | Why Priority |
|----------|------|----------|---------|-------------|
| English | en | 370M | USA, UK, Australia, Canada | Market default; highest revenue |
| Spanish | es | 460M | Mexico 130M, Latin America | 2nd largest; Mexico critical |
| Mandarin Chinese | zh-Hans | 918M | China 1.4B, Singapore | Largest speaker base; complex script |
| Traditional Chinese | zh-Hant | 85M | Taiwan 23M, Hong Kong 7.5M | Different script; separate market |
| Arabic (MSA) | ar | 400M | Middle East, North Africa | Large formal-business use |
| French | fr | 280M | Sub-Saharan Africa 300M+ | Colonial legacy; Africa growth |
| Portuguese (Brazilian) | pt-br | 220M | Brazil 211M | Emerging market; distinct from European |
| German | de | 95M | Germany, Austria, Switzerland | High revenue; mature market |
| Russian | ru | 258M | Russia, Eastern Europe | Large diaspora; regional hub |
| Japanese | ja | 125M | Japan, diaspora | Mature, high-revenue; complex script |
| Korean | ko | 81M | South Korea, diaspora | High-revenue; unique script |
| Hindi | hi | 345M | India 1.4B population | Fastest-growing major market |
| Vietnamese | vi | 85M | Vietnam 97M | Fast-growing; 2G/3G prevalent |

**Cost:** $8,000–15,000 per language ($15–35/word; 40,000–60,000 words typical).

---

#### Tier 2: Machine Translation + Native Review

**Investment:** 60% | **Timeline:** 6–8 weeks | **Maintenance:** Community-driven

**Quality Standard:** Machine translation baseline, native speakers review flagged segments, BLEU score >40, post-launch iteration.

**Tier 2 Candidates:**

| Language | Code | Speakers | Markets | MT Quality | Reason |
|----------|------|----------|---------|-----------|--------|
| Indonesian | id | 43M + 150M L2 | Indonesia 270M | 75% | High speakers; consistent orthography |
| Thai | th | 60M | Thailand 69M | 65% | Growing; challenging script; 2G critical |
| Turkish | tr | 88M | Turkey 85M | 70% | Regional hub; agglutinative (complex) |
| Polish | pl | 38M | Poland 37M | 60% | EU market; Slavic (lower MT quality) |
| Swahili | sw | 80M + 150M L2 | Kenya, Tanzania, Uganda | 55% | Largest African language; growing |

**BLEU Score Guide:**
- \>70: High-quality; minimal review needed
- 40–70: Acceptable; flag domain-specific terms for review
- <40: Escalate to Tier 1 or defer

**Workflow:**
1. Generate MT using Google Translate API v3 or DeepL
2. Calculate BLEU score
3. Intelligently flag segments (payment, legal, health terms; >30% length difference; proper nouns)
4. Recruit 3+ native speakers
5. Review flagged segments (compensation: $25–40/hour)
6. Integrate feedback; create terminology glossary
7. Deploy with feedback mechanism
8. Iterate monthly based on user reports

---

#### Tier 3: Machine Translation Only

**Investment:** 20% | **Timeline:** 1–2 weeks | **Maintenance:** Automated

**Quality Standard:** Automated nightly MT pipeline; no manual review; user feedback collected for potential promotion to Tier 2.

**Tier 3 Candidates:** Languages with <10K estimated users; humanitarian/linguistic importance.

**Examples:** Amharic, Yoruba, Lao, Tigrinya, Nepali.

**Process:**
- Automated nightly MT updates
- In-app "Report translation issue" mechanism
- Community feedback drives potential Tier 2 promotion
- Discontinuation policy: <0.1% user base for 12+ months → notify 6 months before removal

### 1.1.3 Dialect, Script, and Transliteration Strategy

#### Arabic Dialect Strategy

**Reality:** Modern Standard Arabic (MSA) differs from colloquial dialects; native speakers often struggle with formal MSA (learned in school, not home).

| Variant | Speakers | Context | Examples | Strategy |
|---------|----------|---------|----------|----------|
| **Modern Standard (MSA)** | 400M passive | Formal, news, government | Legal docs, formal business | Use for regulatory products |
| **Egyptian Arabic** | 100M | Casual, media, entertainment | Consumer apps, social | Use for consumer engagement |
| **Levantine Arabic** | 20M | Casual, regional media | Apps in Levant | Use for Levant-targeted products |
| **Gulf Arabic** | 20M | Business, formal (Gulf states) | Finance, enterprise | Use for Middle East business |
| **Moroccan Arabic (Darija)** | 20M | Casual, informal | Consumer products | Lower priority; written forms rare |

**Implementation:**

### 1.1.4 Name Field Architecture

**Problem:** Western "First Name + Last Name" model excludes 50%+ of world's population using different conventions.

#### Regional Naming Conventions

| Region | Pattern | Example | Why Different |
|--------|---------|---------|--------------|
| **East Asia** | Family + Given | 李明 (Li Ming) | Hierarchical; family-first cultural value |
| **Hungary, Georgia, Iceland** | Family + Given | Kiss Ferenc | Historical convention |
| **Indonesia** | Mononymic | Suharto, Cher | Some use single name only |
| **Iberian (Spain, Portugal)** | Given + Family1 + Family2 | Juan García López | Two surnames (paternal + maternal) |
| **Arab World** | Given + Father + Grandfather + Tribe | Muhammad Ali Husain Al-Ahmadi | Patrilineal genealogy |
| **Netherlands** | Given + Particle + Family | Jan van der Meer | Particles (van, de, ter) + surname |

#### Database Schema

```javascript
{
  user_id: "12345",
  name_parts: {
    display_name: "李明",        // What appears on UI
    legal_name: "李明",          // For contracts
    family_name: "李",
    given_name: "明",
    name_prefix: null,           // Dr., Sr., etc.
    name_suffix: null,           // Jr., Sr., III
    middle_name: null,
    patronymic: null,
    romanization: "Li Ming"      // Pinyin for international docs
  },
  name_format_preference: "family_given",  // How to display
  writing_system: "Han"                    // Chinese characters
}
```

### 1.1.5 Address Format Flexibility

**Problem:** Address components vary globally; Western "Street, City, Zip, Country" doesn't fit Japan, Netherlands, or many other regions.

#### Regional Variations

| Country | Order | Example |
|---------|-------|---------|
| **USA** | Street, City, State, ZIP | 123 Main St, Springfield, IL 62701 |
| **UK** | Street, Town, Postcode | 123 High Street, Oxford, OX1 2JD |
| **Japan** | Prefecture, City, Ward, Block, Building | 〒100-0001 東京都千代田区丸の内1–1 |
| **Netherlands** | Street + Number, Postcode, City | Straat 123, 1000 AA Amsterdam |
| **India** | House, Street, Area, City, Postal Code | 123 Elm Road, Koramangala, Bangalore 560034 |

    case 'in':

      break;
